## Hand-transcribed copies and their parity suites

`sim/vendor/bitburner/` is generated by `bun run vendor` and is the engine
truth, but only `sim/` may import it (`tests/boundaries.test.ts`). Code that
needs the same values outside `sim/` therefore transcribes them, and every
transcription is pinned by a parity suite that lives in `sim/` — the one place
allowed to read both sides:

| Transcription | Why it cannot import the vendor | Parity suite |
|---|---|---|
| `shared/formulas.ts` | ships inside the game bundle | `sim/tests/formulas-parity.test.ts` |
| `shared/features/bitnode.ts` | pure shared data read by `ui/` | `sim/tests/bitnode-parity.test.ts` |

After a vendor bump, a failing parity suite is the expected signal, not a
regression: update the transcription to match the new game data. Without them a
transcription rots silently — the BitNode one would keep diffing the active
node's multipliers against a stale baseline and report the wrong fields as
"changed".
