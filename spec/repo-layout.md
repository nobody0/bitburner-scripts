# Repository layout

Four parts, one rule each:

| Directory | Rule |
|---|---|
| `game/`   | The ONLY code that reaches the game. Entrypoints listed in `bitburner.config.json` (validation rejects sources outside `game/`), bundled standalone by esbuild, pushed over the Remote File API. Currently deliberately minimal: `start.ts` (bootstrap controller), `lib/telemetry.ts`, `lib/watched-ns.ts`, `lib/dodge*.ts`, and the starter worker. |
| `shared/` | Pure code used by two or more parts: telemetry schema, the WorldView/Action/Planner seam, goals + the stream reducer, strategy. No ns, no Bun APIs, no `__TELEMETRY__`. |
| `sim/`    | The test loop. `vendor/bitburner/` (generated by `bun run vendor` from the pinned tag — DO NOT EDIT), `core/` (transcribed effects, mocks, rng), `clock.ts`, `world.ts`, `run.ts`, `compare.ts`, and simulator-specific tests under `tests/`. Runs under Bun only. |
| `ui/`     | The external UI process: telemetry hub (`server.ts`, port 12526) + browser viewer (`public/index.html`). Runs under Bun only. |

Plus: `tools/` (build/sync/vendor tooling), `spec/` (these documents),
`tests/` (cross-project and tooling tests), `types/` (game-provided
NetscriptDefinitions), `runs/` (gitignored
JSONL telemetry, one file per run).

## Daily commands

```
bun run dev          # sync-on-save to the game (telemetry ON)
bun run dev:perf     # same, telemetry compiled out
bun run ui           # telemetry hub + viewer at http://127.0.0.1:12526
bun run sim -- --goal earn:1e6 --seed 1     # simulate; JSONL lands in runs/
bun run sim:compare runs/a.jsonl runs/b.jsonl
bun run vendor       # re-extract game formula core from the pinned tag
bun run typecheck && bun run typecheck:vendor && bun test
```

## Current intent (keep it simple)

The in-game footprint stays at "stub + logging" until the sim and UI have
proven a strategy worth shipping; features land one by one behind the seam
(`shared/world.ts`). The planner in `shared/strategy/` currently serves the
sim harness only — `game/start.ts` does not drive it yet.
