# BN14 — IPvGO Subnet Takeover

> *"Territory exists only in the 'net"* · theme: [`go`](../features/go.md)

**In-node:** nothing gated. **IPvGO is playable in every BitNode with no
Source-File** — the `Go` interface declares no Source-File requirement
(`types/NetscriptDefinitions.d.ts:5541-5545`) and `go.getGameState()` costs 0 GB
(`:5672`). What BN14 changes is that Go is *worth* playing: `GoPower` 4
(`sim/vendor/bitburner/src/BitNode/BitNodeMults.ts:484`) against 1 everywhere
else (`BitNodeMultipliers.ts:98`). Winning subnets grants node power — a player
multiplier keyed per opponent (`Go/effects/EffectOracle.ts:9-15`) — and, against
a joined faction, faction favor (`:17-31`). `go.cheat` is separate and needs
SF14.2 (`types/NetscriptDefinitions.d.ts:5388`). Rules, opponents, RAM costs and
reward maths: [`../features/go.md`](../features/go.md).

## SF14

| Level | Effect |
|---|---|
| 1 | Node-power effect ×2; winstreak favor cap 100 000 → 200 000 rep equivalent |
| 2 | Permanently unlocks the `go.cheat` API (`types/NetscriptDefinitions.d.ts:5388`); cap → 300 000 |
| 3 | Cap → 400 000 |

The SF14 level scales exactly one value: the favor cap, via `getMaxRep()`
(`Go/effects/EffectOracle.ts:17-31`). The node-power doubling is **binary on
holding SF14 at any level**, not per level:
`sourceFileBonus = activeSourceFileLvl(14) ? 2 : 1` (`:11`). Because a favor
event converts `maxRep / 200`, the cap moves the per-event grant from 500 to
1000 / 1500 / 2000 ([`../features/go.md`](../features/go.md)).

## Notes

- `FactionWorkRepGain` and `CompanyWorkRepGain` both 0.2 — the only node where
  both sit that low (`BitNodeMults.ts:507-508`) — turn the normal rep engine
  off, so Daedalus favor from Go is the substitute.
- `HackingSpeedMultiplier` 0.3 is the game's lowest, shared only with BN15's 0.6
  (`:487`, `:530`). It retimes every batch rather than scaling yield.
- `CrimeSuccessRate` 0.4 is unique to BN14; no other node changes the field.
