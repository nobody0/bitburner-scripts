# BN9 — Hacktocracy

> *"Hacknet Unleashed"* · theme: `hacknet`

**In-node:** the **Hacknet Server** — an upgraded Hacknet Node producing
**hashes** instead of money. Hashes buy money, server RAM/cores, research,
corporation funds, Bladeburner rank/SP, contract generation, and reductions to a
target server's minimum security / increases to its maximum money. Hacknet
Servers also contribute RAM to the fleet.

## Reading

- `CloudServerLimit: 0` plus `HomeComputerRamCost: 5` means **the only way to get
  RAM is Hacknet Servers**. This is the node that most directly attacks our
  architecture: the RAM heap, dodge placement and reserve calculation all assume
  a purchasable fleet. Here the fleet *is* the hacknet.
- `HackExpGain` 0.05 × `HackingLevelMultiplier` 0.5 makes hacking 6000 an
  enormous investment. Hash-bought server improvements are the intended path.

## SF9

| Level | Effect |
|---|---|
| 1 | Permanently unlocks Hacknet Servers in other BitNodes |
| 2 | Start each new BitNode with **128 GB** home RAM |
| 3 | Start each new BitNode with a highly-upgraded Hacknet Server |

Plus hacknet production +12% / 18% / 21% and matching cost reduction. Levels 2
and 3 apply on **entering a BitNode, not on installing augmentations**.

SF9.2's 128 GB is one of the highest-value permanent upgrades in the game for an
automation codebase — roughly the difference between affording one dodge and
affording the probe roster.

## For our code

- `hacknet` must distinguish **Nodes** from **Servers** and run a hash-spending
  strategy, not a buy/upgrade loop.
- The RAM heap must treat hacknet servers as first-class fleet hosts.
- Purchased-server logic must degrade cleanly when `CloudServerLimit` is 0
  rather than retrying purchases forever.
