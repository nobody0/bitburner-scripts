and the ability to short and place limit/stop orders.

## Reading

- `ScriptHackMoney` 0.3 **and** `ScriptHackMoneyGain` 0 together: the server
  loses money and you gain none. Hacking survives only as **experience** and as
  **stock manipulation** — hacking drives a symbol down, growing drives it up.
  That is the node's actual mechanic.
- The finish line is BN1's, but every route to it except the market is closed.
- `FavorToDonateToFaction` 0 means all rep is buyable from turn one, so the
  reset loop collapses to "trade, donate, buy augs".

## For our code

Implemented. What the node demands and where it lives:

- **A real trading strategy.** `shared/strategy/stock/` — `market.ts` models the
  price tick (the shared volatility roll, the 75-tick regime cycle, the spread,
  the second-order forecast), `history.ts` estimates forecast from prices and
  establishes the cycle clock once 4S exposes a boundary. The shared tick
  magnitude plus the vendored discrete volatility
  ranges usually has one solution, revealing each live volatility after one
  basket tick; ambiguous or corpus-inconsistent observations fall back to the
  measured estimator. `decide.ts` spends money. Those published ranges are fair
  game knowledge, while the actual values rolled for the current run still come
  only from observation.
  The node's free WSE + TIX means the
  ladder starts at the $25b 4S API, which is the one 4S purchase a script can use.
- **Shorts.** Available in-node without a source file, so `canShort` is true and
  the solver takes the bearish half of the book.
- **Hack/grow-as-manipulation coordination.** `stock` publishes a per-host intent
  and a dollar value per influencing op; `solveCycle` adds it to the same
  `$/GB/sec` target score, and the dispatcher sets `{stock: true}` on the grow for
  a long and the hack for a short — never both, since their successful
  steady-state influences oppose each other. The arbiter
  does not need to model the contention because it is priced INTO the score both
  sides already compare on. See [spec/targeting.md](../../targeting.md).
- **`ScriptHackMoneyGain: 0` is now a first-class input**, not an omission.
  `HackContext.scriptHackMoneyGain` scales the hacking income term and NOT the
  manipulation term, because influence is computed from `moneyDrained` before the
  player's cut. Without it every BN8 target reported as profitable while earning
  nothing. The farm keeps running here for two real reasons — experience, and
  price movement.
- **No stock allocation cap or BN8 priority override.** A position proposes the
  full liquid-cash amount, bounded only by public `maxShares` and transaction
  economics. Stock positions, market unlocks, Hacknet and hacking infrastructure
  all use the shared `income:investment` band, where the money arbiter ranks them
  by return per dollar per second. In BN8 the non-stock income returns collapse
  toward zero, so stocks naturally receive almost all deployable money without a
  BitNode-specific spending rule.
- **Manipulation follows owned exposure.** The worker's stock flag is enabled
  only for a live position, only on a publicly mapped farmable host, and only
  while the current signal still favors the held side. There is no speculative
  manipulation to manufacture an entry signal. With no profitable money or
  manipulation target, dollar score stays the primary objective but ties at
  zero are broken by expected hacking experience per GB-second. Hacking selects
  that farm even when it is cold, prepares it through the normal farm path, and
  then batches it for experience. BN8 reserves one fleet host so that fallback
  cannot starve the market sampler or trade action; the reservation includes
  the dodge stub's own RAM as well as its dynamic API cost.
- **`FavorToDonateToFaction: 0`** means all rep is buyable from turn one, so the
  liquidation rule matters more here than anywhere: cash out, donate, install.
