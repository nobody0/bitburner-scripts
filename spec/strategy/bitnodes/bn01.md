# BN1 — Source Genesis

> *"The original BitNode"* · theme: [`hacking`](../features/hacking.md)

**In-node:** nothing is modified. "It has no special modifications or
mechanics" (`src/BitNode/BitNode.tsx:51` **[src]**), and the code agrees: BN1 is
the `DEFAULT_BITNODE_MULTIPLIERS` baseline every other node is diffed against.
Strategy tuned here therefore carries no node-specific allowance, and every
assumption it makes has to be rechecked in the node it moves to.

## Multipliers

**Zero changed fields.** `bitNodeMultipliers(1, 0)` returns the defaults
unaltered (`shared/features/bitnode.ts:42-97`, pinned field-by-field by
`sim/tests/bitnode-parity.test.ts`), so there is no table to print. Every field
is `1` except the two that are not multipliers: `StaneksGiftExtraSize` `0`
(additive) and `DaedalusAugsRequirement` `30` (a count).

`WorldDaemonDifficulty` `1` → `worldDaemonSkill(1)` = **3000**
(`shared/features/bitnode.ts:368-378`).

## SF1

Destroying BN1 grants SF1, or upgrades an owned SF1 to a maximum of level 3
(`src/BitNode/BitNode.tsx:54-55` **[src]**).

| Level | Total | Gain over prior level |
|---|---:|---:|
| SF1.1 | ×1.16 | +16 points |
| SF1.2 | ×1.24 | +8 |
| SF1.3 | ×1.28 | +4 |

`mult = Σ 16 / 2^i` over the owned levels, `incMult = 1 + mult/100`
(`sim/vendor/bitburner/src/SourceFile/applySourceFile.ts:17-22`). The totals are
cumulative, not three bonuses that stack.

`incMult` multiplies `hacking`, `hacking_chance`, `hacking_speed`,
`hacking_money`, `hacking_grow`, the four combat skills, `charisma`, all six
`*_exp`, `company_rep`, `faction_rep`, `crime_money`, `crime_success`,
`hacknet_node_money` and `work_money` (`applySourceFile.ts:23-43,48`).

`decMult = 1 / incMult` multiplies the four Hacknet **cost** multipliers —
purchase, RAM, core and level (`:22,44-47`). At SF1.3 that is 1 / 1.28 =
**0.78125**. The in-game text claims SF1 "increases all of the player's
multipliers" (`BitNode.tsx:60-61` **[src]**); the code lowers these four. Code
wins.

Home RAM on entering a new BitNode is **32 GB** with SF1 at any level, 8 GB
without it, and 128 GB when SF9 ≥ 2 takes the branch first; `cpuCores` is reset
to 1 either way (`src/Prestige.ts:246-253`, in `prestigeSourceFile` **[src]**).

## Notes

- The Red Pill costs **2 500 000 rep and $0** at Daedalus, and is `isSpecial`
  (`sim/vendor/bitburner/src/Augmentation/AugmentationTable.ts:2292-2302`).
- Owning it is not enough. The `The-Cave` ↔ `w0r1d_d43m0n` network link is
  created during an **install**, gated on `hasAugmentation(TheRedPill, true)` —
  installed, not queued (`src/Prestige.ts:175-182`, in `prestigeAugmentation`
  **[src]**; `shared/strategy/progression/endgame.ts:28`).
- `w0r1d_d43m0n` requires hacking **3000** and **5 ports**; `The-Cave` in front
  of it requires hacking **925** and 5 ports
  (`sim/vendor/bitburner/src/Server/data/ServerMetadata.ts:2245-2292`).
- Alternative finishes, neither needing The Red Pill from Daedalus: all 21 black
  operations ([`bladeburner.md`](../features/bladeburner.md)) or the darknet
  labyrinth's Red Pill reward, which needs BN15 or SF15
  ([`dnet.md`](../features/dnet.md)).
- Route choice is [`endgame.md`](../endgame.md); the reset loop, augmentation
  pricing and the post-install regrow are
  [`progression.md`](../features/progression.md); per-feature unlock gates are
  [`features/`](../features/README.md).
