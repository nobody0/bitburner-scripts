# BN1 — Source Genesis

> *"The original BitNode"* · theme: `hacking`

The only note written as a playbook. BN1 is the tuning target.

## What it changes

**Nothing.** `getBitNodeMultipliers(1, lvl)` returns `new BitNodeMultipliers()`
— every field at default. BN1 *is* `DEFAULT_BITNODE_MULTIPLIERS`, which is why
`changedMultipliers()` renders empty here.

So every strategy tuned in BN1 is tuned against the unmodified game. The other
fourteen notes exist to show which BN1 conclusions are multiplier-fragile.

## Win condition

1. Own **The Red Pill** — Daedalus, 2 500 000 rep, **$0**, `isSpecial`.
2. **Install** it. `Prestige.ts:175` links `The-Cave ↔ w0r1d_d43m0n` only when
   `hasAugmentation(TheRedPill, true)`. Buying is not enough — the server is not
   in the graph until an install happens with the aug owned.
3. Reach `w0r1d_d43m0n`: **hacking 3000**, **5 ports** (`servers.ts:1530`;
   `ServerHelpers.ts:384` applies `WorldDaemonDifficulty`, which is 1 here).
   `The-Cave` en route needs hacking 925.
4. End the node. Via ns this is `singularity.destroyW0r1dD43m0n(nextBN)`, and
   its check is **`hacking >= required && hasAdminRights`** — root, *not* a
   manual backdoor; it sets `backdoorInstalled` itself
   (`NetscriptFunctions/Singularity.ts:1170`). The terminal route does require
   backdooring.

The same call accepts a **completely different** proof: all 20 Bladeburner
black operations complete, with no Red Pill and no hacking requirement at all.
That is not a BN6 special case — it works in any node where we have
Bladeburner. See [`bn06.md`](bn06.md).

**The trap, and the biggest schedule risk in BN1:** step 2 is an install, which
resets hacking to 1. The run is not "reach 3000 and win" — it is "reach 3000
*after* the install carrying the Red Pill". So the Red Pill should ride the same
install as the largest hacking-multiplier batch we can afford, and the regrow is
a planned phase. A planner that misses this under-estimates time-to-BN1 by a
full regrow.

Reaching Daedalus (`FactionTable.ts`):

| Requirement | BN1 value |
|---|---|
| Augmentations owned | **30** (`DaedalusAugsRequirement`) |
| Money | $100b |
| Skills | hacking ≥ 2500 **or** all four combat ≥ 1500 |

The count is *owned*, so stacked NeuroFlux levels pad it.

**With SF15 there is a second route.** BN1 leaves
`DarknetLabyrinthRewardsTheRedPill` at its default of 1, and the darknet
labyrinth awards The Red Pill after its six-augmentation sequence
(`DarkNet/effects/labyrinth.ts:424`). SF15.1 unlocks the full dark web in every
BitNode, so a returning player can in principle reach the Red Pill **without
Daedalus's 2 500 000 rep at all**. Whether that is faster than the faction route
is unmeasured — but it means "30 augs + $100b + hacking 2500" is a route, not
*the* route, and `progression` should not hard-code the Daedalus path.

## What is available

BN1 unlocks nothing. Everything beyond the base game depends on Source-Files
already held, which makes "which SFs do we carry" the parameter deciding what
the controller can attempt:

| Available in BN1 | Requires |
|---|---|
| `hacking`, `hacknet`, `side`, `progression`, `go` | always |
| `stock` | buy WSE+TIX in-node, or SF8 |
| `factions`, automated `career` | **SF4** |
| `gang` | SF2 **and** karma ≤ −54 000 |
| `corp` / `bladeburner` / `sleeves` / `stanek` / `dnet` | SF3 / SF6 or SF7 / SF10 / SF13 / SF15 |

**A first-ever BN1 has no Source-Files**, so there is no `ns.singularity.*` and
the reset loop — the actual content of BN1 — is not automatable. `caps.unlocked
.factions === "no"` in BN1 is normal, not a bug.

Two different runs, and we should say which we optimize:

- **Cold BN1** (no SFs): optimize the automatable half, emit a manual to-do list
  for the rest.
- **Returning BN1** (SF4, ideally 4.3 for 1× Singularity RAM): fully
  automatable. "Near-perfect" is only meaningful here.

## Route

**1 — Fleet.** Scan, nuke, deploy, farm. Buy TOR ($200 000, `Constants.ts:44`)
early: it converts port openers from a *work-slot* cost to a *money* cost, and
the work slot is the scarcer resource.

| Program | Darkweb | Create at hacking |
|---|---|---|
| BruteSSH.exe | $500k | 50 |
| FTPCrack.exe | $1.5m | 100 |
| relaySMTP.exe | $5m | 250 |
| HTTPWorm.exe | $30m | 500 |
| SQLInject.exe | $250m | 750 |
| Formulas.exe | $5b | 1000 |

**2 — Hacking factions.** The BN1 spine. Costs only hacking level and ports —
no karma, no combat, no job, no travel:

| Faction | Backdoor | Augs |
|---|---|---|
| CyberSec | `CSEC` | 6 |
| NiteSec | `avmnite-02h` | 11 |
| The Black Hand | `I.I.I.I` | 11 |
| BitRunners | `run4theh111z` | 14 |

Everything else on the faction board is optional in BN1 and must be justified
against this chain.

**3 — Other factions, only if they pay.** Sector-12 ($15m, be there) and Tian
Di Hui ($1m, hacking 50, Chongqing/New Tokyo/Ishima) are nearly free. The crime
factions demand combat stats and karma, which compete with hacking for the work
slot; their value is padding the Daedalus count of 30. Whether that beats
stacking NeuroFlux is a real question and a good early simulator target.

**4 — The reset loop.** Where BN1 is won or lost:

- Faction **rep resets to 0 on install** and converts to permanent **favor**
  (`favor.ts:addRepToFavor`). Favor gives +1% rep rate per point and unlocks
  **donations at 150 favor** (`BaseFavorToDonate`, `Constants.ts:31`) at
  **$1e6 per rep** (`DonateMoneyToRepDivisor`, `:33`).
- So Daedalus's 2.5m rep is $2.5e12 of donation at 1× rep mult, or a lot of
  favor-boosted faction work. Which is cheaper depends on farm income — exactly
  what the simulator should answer.
- Augs escalate **×1.9 per queued aug** (`MultipleAugMultiplier`, `:41`), so
  batch size has a cost curve; "buy everything, then install" is not
  automatically right.
- Install also resets (`PlayerObjectGeneralMethods.ts`, `prestigeAugmentation`):
  money → $1000, city → Sector-12, jobs, purchased servers, all skills, **kills**,
  faction membership. It does **not** reset karma, favor, home RAM or programs.

**5 — Endgame.** 30 augs + $100b + hacking 2500 → Daedalus → 2.5m rep → Red
Pill → install → regrow to 3000 → backdoor `w0r1d_d43m0n`.

## For our code

- `progression` must model the **Red-Pill install regrow** as a phase.
- `progression` must pick **batch size** against ×1.9 escalation vs. the
  rep→favor conversion, not just "buy what we can afford".
- `factions` must treat **favor** as persistent and rep as perishable, and know
  the 150-favor donation cliff.
- `career` must encode that **kills are per-install, karma is per-node**.
- `progression` must detect **cold BN1** (no SF4) and report manual steps
  instead of waiting on capabilities that will never arrive.
- A BN1 goal composition in `shared/goals/presets.ts` — a Daedalus milestone
  (`augCount:30`, `money:1e11`, `skill:2500`), then a Red Pill milestone — so
  time-to-BN1 is measurable at all.
