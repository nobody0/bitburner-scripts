# BN4 — The Singularity

> *"The Man and the Machine"* · theme: `factions`

**In-node:** the **Singularity functions** (`ns.singularity.*`) — working for
factions and companies, crime, travel, buying and installing augmentations,
creating programs. In-node they cost full RAM; the SF4 divisor applies to
*other* BitNodes.

**The most important node for us.** Without SF4 there is no `factions`, no
automated `career`, and therefore no automated reset loop — which is what
actually beats BitNodes.

## Reading

- Every income cut and **all five exp sources halved or worse**. Nothing here is
  a buff — BN4's reward is the API, not favourable rules. Optimize for
  finishing, not for speed within it.
- `HacknetNodeMoney: 0.05` means `hacknet` should switch itself off; a driver
  that keeps buying here burns money.

## SF4

Singularity functions everywhere, with a RAM divisor: **16× / 4× / 1×** by
level.

The 16× at SF4.1 shapes our probe budget: one `SingularityFn3` call is **80 GB**
at level 1, which `spec/features.md` flags as an indivisible blocker no
dodge-splitting fixes. **SF4.3 is worth grinding for on our terms specifically**
— it is the difference between a feature we can drive and one we can only poke.

## For our code

- `progression` should treat **SF4 level** as a planning input: it changes which
  features are affordably drivable, not just how fast.
- Probe budgeting prices Singularity calls via `ns.getFunctionRamCost`, which
  already folds in the divisor — verify that path is exercised at level 1, not
  only at level 3.
