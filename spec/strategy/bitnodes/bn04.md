# BN4 — The Singularity

> *"The Man and the Machine"* · theme: [`factions`](../features/factions.md)

**In-node:** the **Singularity functions** (`ns.singularity.*`) — working for
factions and companies, crime, travel, buying and installing augmentations,
creating programs. They are usable without SF4 only here
(`types/NetscriptDefinitions.d.ts:1907-1911`). In-node they cost their base RAM:
the Singularity multiplier is 1× whenever `bitNode === 4`, regardless of SF4
level (`sim/ns/ram-costs.ts:589-597`, transcribed from `RamCostGenerator.ts`
`SF4Cost` @ v3.0.1). The 16× / 4× / 1× band applies in *other* BitNodes.

Without SF4 there is no automated [`factions`](../features/factions.md) and no
automated [`career`](../features/career.md): installing augmentations is itself a
Singularity call, so the reset loop cannot be driven
(`shared/features/unlock.ts:124-127`).

## SF4

SF4 applies no stat multipliers at any level:
`sim/vendor/bitburner/src/SourceFile/applySourceFile.ts:74-77` is
`case 4: // No effects, just gives access to Singularity functions`. What each
level changes is the RAM multiplier on every `ns.singularity.*` call outside BN4
(`sim/ns/ram-costs.ts:591-597`):

| SF4 level | Singularity RAM multiplier |
|---|---|
| 0 (none) | API unusable outside BN4 |
| 1 | **16×** |
| 2 | 4× |
| 3+ | 1× |

Level 1 carries the same 16× as no SF4 at all; only the access changes.

## Notes

- `SingularityFn3` is 5 GB base (`sim/ns/ram-costs.ts:53`), so one such call —
  `purchaseAugmentation`, `installAugmentations`, `commitCrime`,
  `getOwnedAugmentations` — is **80 GB** at SF4 level 1. That is a single
  indivisible allocation; splitting a probe across scripts does not reduce it
  (`game/lib/probes/index.ts:140`, `game/lib/dodge.ts:53`).
- `HacknetNodeMoney` 0.05 is the lowest fixed non-zero value of that field in
  any BitNode (BN8 is 0, BN12 scales as `1/1.02^lvl`); see
  [`hacknet.md`](../features/hacknet.md) for the payback consequence.
